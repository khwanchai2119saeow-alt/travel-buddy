# 🇯🇵🇨🇳 ผู้ช่วยเที่ยว ญี่ปุ่น · จีน (PWA ฟรี 100%)

แอป iPhone (PWA หน้าตาแบบ iOS รองรับโหมดมืด) สำหรับเที่ยว **หลายทริป** ทั้งญี่ปุ่นและจีน 2 คน กระเป๋าเงินร่วมกัน
UI เป็นภาษาไทยทั้งหมด ใช้ออฟไลน์ได้ ไม่มีเซิร์ฟเวอร์ ไม่มีค่าใช้จ่าย ไม่ต้องผูกบัตร

> ✅ build / typecheck ผ่าน และทดสอบทุกหน้า + โหมดออฟไลน์บนคอมแล้ว (ยังไม่ได้ทดสอบกล้อง/เสียง/GPS บนมือถือจริง)

## ฟีเจอร์

| หมวด | สิ่งที่ทำได้ |
| --- | --- |
| เที่ยวเป็นกลุ่ม | สมาชิกกี่คนก็ได้ · แท็กใครจ่าย/หารกับใคร · สรุปรายคน + ใครต้องโอนให้ใคร (โหมดหารกัน) · เชิญเพื่อนด้วย QR · ส่ง/รับอัปเดตทาง AirDrop/LINE/WeChat (ไม่มีเซิร์ฟเวอร์) |
| หลายทริป | สร้างทริปได้ไม่จำกัด แต่ละทริปมีประเทศ (🇯🇵/🇨🇳) วันที่ สกุลเงิน เรท ล็อตแลกเงิน แผนเที่ยว ค่าใช้จ่ายของตัวเอง · สลับทริปได้ · จบทริปแล้วเก็บสรุป PDF + สำรองเฉพาะทริป แล้วลบเพื่อลดขนาดข้อมูล |
| ประเทศจีน | เงินหยวน (มีทศนิยม) · สแกนใบเสร็จ/ป้ายภาษาจีน (OCR chi_sim ออฟไลน์) · วลีจีนกลาง 55+ ประโยคพร้อมคำอ่านไทย · เสียง zh-CN · นำทางด้วย Apple Maps (Google ใช้ในจีนไม่ได้ถ้าไม่มี VPN) · เบอร์ฉุกเฉิน 110/120/119 |
| ค่าใช้จ่าย ส่วนที่ 1 | จดค่าใช้จ่ายล่วงหน้าเป็น **บาท** — ตั๋วเครื่องบิน, ที่พัก, ประกัน, อีซิม, อื่น ๆ |
| ค่าใช้จ่าย ส่วนที่ 2 | จดรายวันเป็น **เงินท้องถิ่น (เยน/หยวน)** — ค่ากิน, ค่าเดินทาง, ช้อปปิ้ง, อื่น ๆ + แท็กใครจ่าย (ไม่บังคับ) + ผูกกับสถานที่ + แนบใบเสร็จ |
| เรทแลกเงิน | ตั้งเรทคงที่เอง หรือเพิ่ม "ล็อตการแลกเงิน" หลายรอบ แล้วแอปคิดเรทเฉลี่ยถ่วงน้ำหนักให้ + ติดตามเยนคงเหลือ |
| กราฟ | แท่งซ้อนสีตามหมวดรายวัน (¥/฿) + เส้นค่าเฉลี่ย **ไม่มีวงเงินบังคับ** + สัดส่วนตามหมวด |
| สแกนใบเสร็จ | ถ่าย/เลือกรูป → Tesseract.js อ่านญี่ปุ่นในเครื่อง → เดาเลขยอดรวม → แก้/เลือกได้ → แปลงเป็นบาท → บันทึกพร้อมแนบรูป · **แปลรายการสินค้าเป็นไทย** (พจนานุกรมในเครื่อง ~260 คำ + แปลออนไลน์ MyMemory สำหรับคำที่ไม่รู้จัก) เดาหมวดให้อัตโนมัติ และเก็บรายการไว้ในโน้ต |
| แปลภาษา | วลีสำเร็จรูป 60+ ประโยค (ออฟไลน์) + คำอ่านไทย + เล่นเสียง ja-JP (Web Speech API) + โหมดโชว์พนักงานตัวใหญ่เต็มจอ + พิมพ์แปล (MyMemory ฟรี ต้องมีเน็ต) |
| แปลป้าย | ถ่ายป้าย → OCR → จับคู่พจนานุกรมป้าย 80+ คำ (รวมป้ายเฉพาะฮอกไกโด: ระวังหมี, ถนนเป็นน้ำแข็ง, ออนเซ็น) |
| แผนเที่ยว + แผนที่ | แผนรายวัน, โรงแรม (รหัสจอง/เช็กอิน), Leaflet + OpenStreetMap (ป้ายชื่อญี่ปุ่นคู่อังกฤษ จากแผ่นแผนที่ฟรีของ openstreetmap.de), หมุดโรงแรม/จุดเที่ยว, เส้นทางตามลำดับ, **แตะหมุดแล้วเด้งการ์ดมีรูปหลายรูป (เลื่อนดูได้ สูงสุด 10 รูป)/โน้ต/ปุ่มนำทาง** · **ติ๊ก "ไปแล้ว" อัตโนมัติเมื่อถึงหมุด** (GPS ขณะเปิดแอป อยู่ใกล้ ~150 ม. ราว 1 นาที เปิด/ปิดได้) |
| นำเข้าแผนจาก CSV | ทำตารางใน Numbers/Google Sheets → นำเข้า (หัวคอลัมน์ไทย/อังกฤษ, วันเป็นเลขหรือวันที่จริง, พิกัดหรือลิงก์ Google Maps) ดูตัวอย่างก่อน กันซ้ำ หาพิกัดที่ขาดผ่าน Nominatim · ส่งออกแผนเป็น CSV ได้ |
| สภาพอากาศรายวัน | พยากรณ์ Open-Meteo (ฟรี ไม่ต้องมี key) ตามที่พัก/จุดแรกของแต่ละวัน: สูงสุด/ต่ำสุด โอกาสฝน หิมะ ลม + คำแนะนำ (รองเท้ากันลื่น พกร่ม) แสดงที่หน้าแรกและแผนรายวัน เก็บแคชไว้ดูออฟไลน์ (พยากรณ์ล่วงหน้าได้ ≤ 16 วัน) |
| สรุปทริป | แคปเป็นรูป PNG / PDF / แชร์ผ่านเมนูแชร์ของมือถือ (html2canvas + jsPDF) |
| ออฟไลน์ | Service Worker + Manifest + IndexedDB (Dexie) + สำรอง/รวมข้อมูล 2 เครื่องด้วยไฟล์ JSON |
| อื่น ๆ | เครื่องคิดเลขราคาป้าย ¥→฿ (บวกภาษีได้), เบอร์ฉุกเฉิน 110/119, บันทึกข้อมูลสำคัญ |

## สแตก

Next.js 15 (App Router, `output: 'export'` = ไซต์สแตติก) · React 19 · TypeScript · Tailwind CSS 3 · Dexie (IndexedDB) ·
Leaflet + OpenStreetMap · Tesseract.js 5 · html2canvas · jsPDF
ไม่มี API ที่ต้องเสียเงิน/ใส่บัตร

## เริ่มใช้งาน

ต้องมี Node.js 20+ (แนะนำ 22)

```bash
npm install          # ติดตั้ง + คัดลอกไฟล์ OCR ไป public/ocr อัตโนมัติ (ให้สแกนออฟไลน์ได้)
npm run dev          # เปิด http://localhost:3000 เพื่อลองบนคอม
npm run build        # สร้างไซต์สแตติกที่โฟลเดอร์ out/
npm run preview      # เปิดดูของที่ build แล้ว
npm run typecheck    # ตรวจชนิดข้อมูล (ไม่บังคับ)
```

> Service Worker ทำงานเฉพาะเวอร์ชัน build จริง (ไม่ทำงานใน `npm run dev`)

### เผยแพร่ให้ใครก็ใช้ได้ (GitHub Pages ฟรี)

ใช้บัญชี GitHub เดิมได้ (มีหลาย repo ได้ ไม่กระทบ repo อื่น เช่นระบบ POS) — สร้าง **repo ใหม่แยก** สำหรับแอปนี้
มี workflow เตรียมไว้แล้วที่ `.github/workflows/deploy.yml` (build + เผยแพร่อัตโนมัติทุกครั้งที่ push เข้า `main`)

1. สร้าง repo ใหม่บน GitHub เช่น `travel-buddy` (**ต้องเป็น Public** — บัญชีฟรีเปิด Pages ได้เฉพาะ repo สาธารณะ
   ในโค้ดไม่มีข้อมูลส่วนตัว/รหัสลับ ข้อมูลทริปอยู่ในเครื่องแต่ละคนเท่านั้น)
2. push โค้ดโฟลเดอร์นี้ขึ้น branch `main`
3. ใน repo: **Settings → Pages → Source = GitHub Actions**
4. รอ Actions สีเขียว (~2–3 นาที) → ลิงก์แอป `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`
5. ส่งลิงก์ให้ใครก็ได้ → เปิดใน **Safari** → แชร์ → **"เพิ่มไปยังหน้าจอโฮม"**

ทดสอบ build แบบซับพาธบนเครื่อง: `NEXT_PUBLIC_BASE_PATH=/travel-buddy npm run build`
(ทางเลือกอื่นที่ไม่ต้องตั้งซับพาธ: Cloudflare Pages — เชื่อม repo, build `npm run build`, output `out`)

หลังติดตั้ง:
- ก่อนบิน **เปิดแอปตอนมีเน็ต 1 ครั้ง** และลองสแกนใบเสร็จ/แปลป้ายของประเทศนั้นสักรูป เพื่อเก็บไฟล์ภาษาไว้ใช้ออฟไลน์
- แอปบนหน้าจอโฮมกับ Safari **เก็บข้อมูลแยกกัน** (iPhone เป็นแบบนี้) — ใช้จากไอคอนหน้าจอโฮมเป็นหลัก

### เที่ยวเป็นกลุ่ม (ไม่มีเซิร์ฟเวอร์)

- **สมาชิกหลายคนต่อทริป** + โหมด **กระเป๋าเงินร่วม** (ไม่คิดเงินคืน) หรือ **หารกัน** (แอปคิดว่าใครต้องโอนให้ใคร)
- **เชิญเพื่อน**: ทริปของฉัน → เพื่อน / สรุป / ลบ… → เชิญเพื่อนเข้าทริป (QR) — ข้อมูลทริปอยู่หลัง `#` ของลิงก์ ไม่ผ่านเซิร์ฟเวอร์
- **เข้าร่วม**: ทริปของฉัน → เข้าร่วมทริปของเพื่อน → ถ่ายรูป QR (อ่านในเครื่อง) หรือวางลิงก์ → เลือกว่าเราคือใคร
- **ส่ง/รับอัปเดต**: ส่งไฟล์ทาง AirDrop (ไม่ต้องใช้เน็ต) · LINE · WeChat แล้วเพื่อนกด "รับอัปเดตจากเพื่อน"
  รายการไม่ซ้ำ (uid) · รายการที่ถูกแก้ทีหลังชนะ (updatedAt) · ข้อจำกัด: **การลบรายการยังไม่ซิงก์** ต้องลบในทุกเครื่อง

## โค้ดแกนหลัก (ไปอ่านที่ไฟล์เหล่านี้)

- **แผนที่ + ป๊อปอัปรูป**: `src/components/MapView.tsx` (หมุด/เส้นทาง/แคชไทล์) → `src/components/PlaceModal.tsx` (การ์ดป๊อปอัป) → ปุ่มนำทางใช้ `https://www.google.com/maps/dir/?api=1&destination=lat,lng` (ลิงก์ฟรี ไม่ต้องใช้ API key มือถือจะเปิดแอป Google Maps ให้เอง)
- **สแกนใบเสร็จ**: `src/lib/image.ts` (`prepareForOcr`) → `src/lib/ocr.ts` (`recognize`) → `src/lib/receipt.ts` (`guessReceipt`) → `src/app/scan/page.tsx`
- **ชั้นเก็บข้อมูลออฟไลน์**: `src/lib/db.ts` (Dexie) + `src/lib/backup.ts` + `public/sw.js`

## ข้อจำกัดที่ควรรู้ (ตรงไปตรงมา)

- **OCR ใบเสร็จญี่ปุ่นไม่แม่น 100%** จึงออกแบบให้ผู้ใช้ตรวจ/เลือกยอดก่อนบันทึกเสมอ ใบเสร็จความร้อนที่จางหรือเอียงอ่านยาก
- **ครั้งแรกต้องมีเน็ตหนึ่งครั้ง** เพื่อให้ Service Worker แคชหน้าแอป (และถ้า `npm install` คัดลอกไฟล์ OCR ไม่สำเร็จ ก็ต้องโหลดไฟล์ภาษาจาก CDN ฟรี ~หลาย MB หนึ่งครั้ง)
- **แปลออนไลน์ใช้ MyMemory** (ฟรี ไม่ต้องสมัคร มีโควตาต่อวัน และคุณภาพเครื่องแปลฟรีไม่สูง) ประโยคสำคัญให้ใช้วลีสำเร็จรูป/โชว์พนักงาน คำอ่านภาษาไทยเป็นการประมาณเสียง
- **ค้นหาสถานที่ใช้ Nominatim ของ OSM** (ฟรี ต้องมีเน็ต เรียกเมื่อกดค้นหาเท่านั้น) ถ้าค้นไม่เจอให้วางลิงก์ Google Maps (ลิงก์ยาวที่มี `@lat,lng`) หรือแตะบนแผนที่แทน
- **แผนที่ภาษาอังกฤษ**: ใช้แผ่นแผนที่ของ OSM เยอรมนี (ฟรี ไม่ต้องมี key) ซึ่งโชว์ชื่อญี่ปุ่นคู่อังกฤษ/โรมาจิ ซูมได้ถึงระดับ 18 ไม่มีแผนที่ฟรีที่เป็นภาษาไทย (CARTO ตอนนี้ต้องใช้ API key แล้ว)
- **แผนที่ออฟไลน์**: แคชเฉพาะไทล์ที่เคยดู/กดปุ่ม "เก็บแผนที่ย่านนี้" (จำกัด ≤ 80 ชิ้นต่อครั้ง ตามนโยบาย OSM ที่ไม่ให้ดาวน์โหลดจำนวนมาก) เหมาะกับย่านที่ใช้บ่อย ไม่ใช่ทั้งฮอกไกโด
- **iOS Safari** อาจล้างข้อมูลเว็บที่ไม่ได้ใช้นาน → เพิ่มลงหน้าจอโฮม และกด "บันทึกไฟล์สำรอง" ทุกคืน
- **ไม่มีซิงก์อัตโนมัติ 2 เครื่อง** (เพื่อให้ฟรีและไม่มีเซิร์ฟเวอร์) ใช้ "ส่งไฟล์สำรองทาง LINE → นำเข้า/รวม" ซึ่งไม่ซ้ำรายการเพราะใช้ uid
- หน้า "สรุปทริป" ไม่ใส่แผนที่ลงรูป (ไทล์ข้ามโดเมนทำให้ html2canvas เสี่ยงภาพว่าง) แสดงรายการสถานที่/รูป/ยอดเงินแทน
- เรทเริ่มต้น ¥100 = ฿23.00 และ 1 หยวน = ฿4.50 เป็นค่าสมมติ **ต้องตั้งเรทจริงของแต่ละทริปที่ ตั้งค่า**
- **ในจีน**: Google Maps/บริการ Google ใช้ไม่ได้ถ้าไม่มี VPN (แอปใช้ Apple Maps แทน) · แผนที่ OSM/แปลออนไลน์อาจช้าหรือถูกบล็อก ส่วนออฟไลน์ใช้ได้ตามปกติ · พิกัดจาก OSM (WGS-84) อาจเยื้องจากแผนที่ในจีนเล็กน้อย
